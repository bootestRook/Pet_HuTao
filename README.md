# 小球对战场

双人联机自动碰撞对战 Web App。可以自己参战，也可以创建观战房间，邀请两名玩家比赛。双方准备后，小球在封闭方形擂台内移动、反弹和碰撞；服务器实时推进战斗，玩家与观战主机同步观看同一场比赛。

当前仅有 2 个小球，各有一个固定效果。武器入口、目录和选装字段已移除。道具、技能和特性的旧内容已清空，保留目录、分类、选装槽位与服务端校验：上限分别为 8 件道具、4 个技能和 1 个特性，当前必须留空。固定效果随小球生效，不占技能或特性槽。无需注册，输入昵称即可开局。每个房间最多两位对战玩家；观战房间另有一位创建者作为观战主机。战斗结束后可以再次对战。

| 小球 | 生命 / 基础碰撞伤害 | 固定效果 |
| --- | --- | --- |
| 蓄力球 | 100 / 10 | 每次撞墙为下一次球体碰撞增加 2 点伤害，最多 +8，碰撞命中后清空。 |
| 回春球 | 100 / 10 | 每次球体碰撞，双方伤害结算后若仍存活，恢复 6 点生命，不超过上限。 |

双方可以选择相同小球，场内用 P1 / P2 区分玩家。以上是本项目的最简规则，并非对参考作品全部角色和数值的复刻。

## Windows 本机与局域网运行

需要 Node.js 24 LTS 和 npm。双击根目录的 `Start-LAN.cmd` 即可启动并打开网页，`Stop-LAN.cmd` 停止后台服务。也可以在项目目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-local.ps1
```

启动器会检查端口；首次缺少依赖时运行 `npm ci`，缺少构建产物时运行 `npm run build`，然后隐藏窗口启动后台服务。重复运行不会再启动第二个进程。普通启动不会每次重新安装依赖。

- 本机打开 `http://localhost:3000/`。
- 同一局域网的其他设备打开启动器显示的 LAN 地址。本机当前地址示例为 `http://192.168.1.202:3000/`；请以每次启动输出为准，路由器分配的地址可能变化。
- 手机与电脑需要在可互访的同一网络。访客 Wi-Fi、路由器的设备隔离功能可能阻止互访。
- 创建房间后，把房间邀请链接发给朋友；在同一个 LAN 地址下打开页面后，也可以用房间码加入。`localhost` 链接只能在这台电脑上使用。

如果 Windows 防火墙拦截局域网访问，在**管理员 PowerShell**中运行一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\allow-lan.ps1
```

此脚本只允许 **Private 网络、LocalSubnet 来源、TCP 3000** 的入站访问，重复运行会更新同名规则。它不会修改网络类型，也不会放行 Public 网络。可添加 `-WhatIf` 只查看操作；如果使用其他端口，应给启动器和防火墙脚本传入相同的 `-Port`。

停止后台服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop-local.ps1
```

停止器核对 PID、进程启动时间、Node 路径和项目入口，不会按端口批量关闭其他程序。运行状态与输出日志保存在 `.runtime/`：

- `server.json`：后台进程标识。
- `server.stdout.log`：标准输出。
- `server.stderr.log`：错误输出。

修改源码后，先停止旧进程，再重建启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop-local.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-local.ps1 -Rebuild
```

更新 `package-lock.json` 后先运行 `npm ci`，再重建。启动器的 `-Port 3001` 可以改用其他端口。前台运行也可以使用：

```powershell
npm ci
npm run build
npm start
```

## 玩法与连接规则

1. 在“进入斗场”区域选择“玩家对战”或“主机观战”，输入昵称创建房间。前者由创建者参战，邀请一位好友；后者由创建者观战，将同一邀请链接发给两位玩家。用邀请链接/房间码加入的访客始终是对战玩家，入口页签只决定新建房间的模式。
2. 在“小球”候选库中查看两个小球的详情并选择。道具、技能、特性页签目前显示空目录和保留的槽位；道具每页显示 4 个槽位。分类搜索、详情、选装、分页系统继续存在，浏览和搜索不会改变搭配。
3. 双方准备后进入 3 秒倒计时，然后自动战斗。更换搭配会取消准备；倒计时中离线会取消开局。伤害、随机结果和胜负由服务器决定。
4. 战斗结束查看结果，再次对战。

观战主机在准备阶段查看两名玩家的搭配摘要和准备状态，正式开战后同步观看战场、战况和结算。主机不占玩家席位，也不能选装、准备或决定再战；这些限制同时由服务器执行。只有两位玩家同意再战后才返回搭配。观战主机掉线不会取消双方倒计时或停止战斗，60 秒内重连/刷新可恢复观战身份；玩家掉线仍遵循原有对战规则。主机主动退出后，已有玩家可以继续比赛；两名玩家都离开后，只要主机仍在房间，就能重新邀请玩家。

刷新页面或短暂断网后，可以在 **60 秒重连窗口**内尝试恢复原席位。战斗由服务器继续推进，恢复后显示当前进度；切换浏览器或清除网站存储可能丢失恢复凭证。

这是单实例内存版本：**停止、崩溃、重启或重新部署服务器会清空房间与对局**。尚无持久账号、成长存档、排行榜、自动匹配或跨进程恢复能力。比赛期间请避免重启服务。

准备期间显示搭配与双方准备状态，正式开始后才显示方形战场、血量、计时和可展开的战斗日志。更换小球会清空旧小球的技能与特性选装，保留道具选装。当前三个可选内容库为空，不存在暗中生效的旧装备。两个小球的数值用于验证最简玩法，尚不构成完整平衡调优。

基础规则：420 × 420 的统一逻辑战场，小球半径 32，移动速度 300 单位/秒。撞墙反弹；两个球接触时分离并反弹，同次接触只结算一轮双方伤害。撞墙本身不扣血，角落一次双轴反弹计一次撞墙。没有定时普攻、随机暴击或闪避。双方碰撞伤害同时结算，倒下的小球不会被回春复活。每局最多 60 秒，超时按剩余生命比例判定；同刻双杀或相同比例为平局。房间 30 分钟没有选装、准备或连接活动后会被回收。

模拟采用固定 10ms 步长，房间每 100ms 广播服务端快照；模拟步长不依赖网络广播频率。初始运动由服务器种子决定，客户端只插值显示坐标，不决定命中、伤害或胜负。

## 扩展搭配内容

`shared/catalog.ts` 的 `LOADOUT_CATEGORIES` 统一声明分类、选装上限和已装备区每页槽位数；客户端展示、房间校验、战斗校验共用这些上限。候选库每页 24 个图标，先搜索再分页；每个分类保留自己的搜索和页码。名称、描述与显式 `keywords` 参与模糊搜索，支持如“回血”等已配置的效果别名，不包含语义模型或自动理解任意同义词。

添加内容时，维护对应目录；技能/特性通过 `petId` 关联所属小球。选装与校验通路已经保留，但新效果必须同时接入碰撞战斗并补充验证，仅加入目录不会自动获得战斗效果。旧版按出手次数触发的效果代码已移除，不作兼容。测试夹具只验证目录、搜索和选装系统的扩展性，不进入正式可玩目录。

## 环境变量

复制 `.env.example` 为 `.env` 后按需修改；不要提交真实 `.env`。

| 变量 | 默认值 / 用途 |
| --- | --- |
| `HOST` | `0.0.0.0`，允许本机与局域网访问。Windows 启动器固定使用此值。 |
| `PORT` | `3000`。Windows 启动器以 `-Port` 参数为准；Docker 内部固定 3000。 |
| `PUBLIC_URL` | 留空适用于本机/LAN；公网填写完整 HTTPS 地址，例如 `https://pet.example.com`，用于生成分享地址。 |
| `ALLOWED_ORIGINS` | 留空采用同源检查；需要允许额外请求来源时，填写逗号分隔的完整来源。浏览器客户端仍按当前页面域名连接，本版前后端同域部署。 |
| `CADDY_DOMAIN` | 仅公网 Compose 使用，填写域名，例如 `pet.example.com`，不要带协议和路径。 |

本机/LAN 运行时保持 `PUBLIC_URL` 为空，或设为其他设备能访问的正确 LAN 地址。公网部署时使用同域网页和 WebSocket，通常无需单独填写 `ALLOWED_ORIGINS`。

## Docker 本机 / LAN 部署

需要 Docker Engine/Desktop 和 Docker Compose。项目根目录执行：

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f app
```

访问宿主机的 3000 端口。默认会映射到所有网络接口，LAN 访问仍取决于宿主机防火墙。停止容器使用 `docker compose down`。

应用镜像以非 root 的 `node` 用户运行，构建后只安装生产依赖。健康检查请求 `/api/health`，核对应用标识和服务状态。

## 公网域名部署

准备一台可访问公网的 Linux 服务器、Docker Compose **2.24.4 或以上**以及一个域名。服务采用单实例常驻进程；自动休眠服务会影响首次访问体验。

1. 上传项目源码和锁文件，不上传本机的 `node_modules/`、`dist/`、`.runtime/` 或 `.env`。
2. 将域名 DNS 的 A 记录指向服务器公网 IPv4。若设置 AAAA 记录，也要确保对应 IPv6 能到达该服务器。
3. 放行服务器安全组/防火墙的 TCP 80、443。
4. 在项目根目录复制并编辑配置：

```bash
cp .env.example .env
```

`.env` 中至少设置：

```dotenv
PUBLIC_URL=https://pet.example.com
CADDY_DOMAIN=pet.example.com
```

5. 使用公网覆盖配置启动：

```bash
docker compose -f compose.yaml -f deploy/compose.public.yaml config
docker compose -f compose.yaml -f deploy/compose.public.yaml up -d --build
docker compose -f compose.yaml -f deploy/compose.public.yaml ps
docker compose -f compose.yaml -f deploy/compose.public.yaml logs -f app caddy
```

覆盖配置清除应用的宿主 3000 端口映射，只公开 80/443。使用官方 Caddy 镜像，将请求转发到应用，自动申请和续期 HTTPS 证书；浏览器通过同一域名的 HTTPS/WSS 连接。证书保存在 Docker 命名卷中。

6. 打开 `https://pet.example.com/api/health`，应返回包含 `ok: true` 和 `app: "pet-arena"` 的 JSON。然后在两个独立浏览器/设备上验证创建房间、加入、准备、自动战斗、刷新重连和结算；其中至少一个设备应使用服务器外部网络。

更新时执行同一组 `-f` 参数的 `up -d --build`。更新会重启应用、清空房间，应在没有比赛时进行。不要执行 `down -v`，除非明确要删除证书卷。

公网配置已经提供，**不表示已购买服务器、配置域名或完成公网部署**。Render/Railway 等托管平台也可以运行应用 Dockerfile，但需要常驻实例、环境变量和 WebSocket 支持；不能只上传静态网页文件来完成联机。
